    The problem: find a song in a playlist

    A music app stores a playlist in a LinkedList<string>. Implement int indexOf(const T& e) const, which returns the index of the first element equal to e, or -1 if there's no match.

    1. Recall what the list gives us.

      "What can I reach directly, and what do I have to walk to?"

      The class has head, tail, and size. Unlike an array, there's no way to jump straight to element i: the only way to reach a node is to start at head and follow next pointers. So the function needs a traversal loop.

    2. Write the function header.

      "Does this function change the list? How should e be passed?"

      template<typename T>
int LinkedList<T>::indexOf(const T& e) const

      Searching doesn't change the list, so the function is const. T could be a large type such as a string, so e is passed by const reference to avoid a copy.

    3. Start a pointer at the head and keep a position counter.

      "I need to know which node I'm on and its index."

      Node<T>* current = head;
for (int i = 0; i < size; i++)

      We use a separate pointer, current, and never move head: moving head would lose the start of the list. The counter i tracks the index of the node current points to.

    4. Check each node, and stop at the first match.

      "The first match is the answer, so I can return right away."

      {
    if (current->element == e)
        return i;                 // first match: done
    current = current->next;      // move to the next node
}
return -1;                        // walked the whole list: no match

      The arrow operator -> reads a member through a pointer. If the loop finishes, every node was checked without a match, so we return -1. Because the loop runs size times, it also works for an empty list: the loop body never runs and the function returns -1.

    5. Trace it before trusting it. Call playlist.indexOf("Imagine"):
      icurrent->elementEqual to "Imagine"?Action
      0"Hello"NoMove to the next node
      1"Imagine"YesReturn 1

      The function returns 1, even though "Imagine" also appears at index 3: indexOf stops at the first match. playlist.indexOf("Help") visits all five nodes and returns -1.

    See the complete function 
    template<typename T>
int LinkedList<T>::indexOf(const T& e) const
{
    Node<T>* current = head;
    for (int i = 0; i < size; i++)
    {
        if (current->element == e)
            return i;
        current = current->next;
    }
    return -1;
}

    Your turn Apply

    Implement int lastIndexOf(const T& e) const, which returns the index of the last element equal to e, or -1 if there's no match.

    A singly linked list can only be walked forward, from head to tail. Think about what you must do differently from indexOf when you find a match.

    The checklist updates as you type. Then predict, or run, the results for the same playlist.

      Your function
      Hint 1: the key difference

      In indexOf, a match ends the search. Here, a later node might also match, so you can't return yet. Remember the index in a variable and keep walking.

      Hint 2: the starting value

      Start the variable at -1. If no node matches, it's never changed, so you can return it as is.

      Show a sample solution 
      template<typename T>
int LinkedList<T>::lastIndexOf(const T& e) const
{
    int result = -1;                 // no match found yet
    Node<T>* current = head;
    for (int i = 0; i < size; i++)
    {
        if (current->element == e)
            result = i;              // remember it, but keep going
        current = current->next;
    }
    return result;                   // 3 for "Imagine", -1 for "Help"
}

      Part B · How should the team build the help desk's Queue? Evaluate
      
    
      The chapter describes two ways to build a Queue class on top of LinkedList:
      

      // Design 1: inheritance (a Queue IS A LinkedList)
template<typename T>
class Queue : public LinkedList<T> { ... };

// Design 2: composition (a Queue HAS A LinkedList)
template<typename T>
class Queue {
public:
    void enqueue(const T& element) { list.addLast(element); }
    T dequeue()                    { return list.removeFirst(); }
    int getSize() const            { return list.getSize(); }
private:
    LinkedList<T> list;
};
      
    
      Which design should the team use for the help desk?
      
      
    
      
    
    
    
      
    
      
      
      An expert's evaluation
      
      
      QuestionDesign 1: inheritanceDesign 2: composition
      
        
          
      Which operations can callers use?Every public LinkedList function, including addFirst, add(index, e), removeLast, and removeAtOnly enqueue, dequeue, and getSize
      
          
      Can someone cut the line?Yes: q.addFirst("Zed") compilesNo: the list is private
      
          
      Is "a queue is a linked list" true?Not really: a queue only uses a list to store elements"A queue has a list" describes it accurately
      
          
      Can the storage change later?Hard: callers may depend on the list functionsEasy: swap the list for another structure without changing callers
      
        
      
      
      Verdict: Design 2. Composition lets the Queue enforce first in, first out, because callers can't reach the list's other operations. Inheritance saves a little typing but exposes operations that break the queue's rules. (Part A's add(index, e) is a deliberate exception that staff use through a separate admin tool, not through the Queue.)

        Show one possible solution (try your own first)

        #include "LinkedList.h"

template<typename T>
class Stack
{
public:
    void push(const T& e) { list.addFirst(e); }        // top = head
    T pop()               { return list.removeFirst(); }
    T& peek()             { return list.getFirst(); }
    bool isEmpty() const  { return list.isEmpty(); }
    int getSize() const   { return list.getSize(); }
private:
    LinkedList<T> list;   // composition: a Stack HAS A LinkedList
};

int main()
{
    Stack<string> undo;
    undo.push("type A");
    undo.push("type B");
    undo.push("bold");
    while (!undo.isEmpty())
        cout << "Undo: " << undo.pop() << endl;
    return 0;
}
        

        Undo: bold
Undo: type B
Undo: type A
        
      
        Justification: the top of the stack is the head. addFirst and removeFirst each change only a couple of pointers, so both are O(1). Using the tail would make push fast (addLast), but removeLast must walk from the head to find the node before the tail, which is O(n) for every Undo.
