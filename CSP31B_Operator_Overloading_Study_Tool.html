1. Operators are functions

RememberUnderstand

You have used overloaded operators since CSP31A. When you write s1 + s2 with two string objects, or v[0] on a vector, C++ calls a function named operator+ or operator[]. The operator syntax is just a friendlier way to write the call.

// What you write
string s1("Washington");
string s2("California");
cout << s1[0];
cout << (s1 + s2);
cout << (s1 < s2);
// What C++ calls
string s1("Washington");
string s2("California");
cout << s1.operator[](0);
cout << operator+(s1, s2);
cout << operator<(s1, s2);

An operator function is named with the keyword operator followed by the symbol. For a member function, the left operand is the calling object (*this) and the right operand is the parameter.

bool Rational::operator<(const Rational& secondRational) const
{
  return compareTo(secondRational) < 0;   // reuse existing logic
}

What you can overload

Almost everything: arithmetic + - * / %, relational < <= == != >= >, [], (), =, += and friends, ++ --, << >>, ! && ||, new delete, and more.

What you cannot overload

?: (conditional), . (member access), .* (pointer-to-member), :: (scope resolution), and sizeof. You also cannot invent new symbols like **.

Common misconception: "Overloading lets me change how an operator is evaluated."

Students sometimes expect that overloading + for their class could make it bind tighter than *, or turn a binary operator into a unary one.

Why it's wrong: overloading only changes what the operator does for your type. Precedence, associativity, and the number of operands (arity) are fixed by the language. r1 + r2 * r3 always computes r2 * r3 first, no matter how you define the functions.

2. Worked example: overloading + and *

UnderstandApply

We'll build operator+ for the Rational class from scratch, exposing the reasoning at every step. Then you'll write operator* yourself. Assume the class stores private numerator and denominator fields and that its constructor reduces the fraction to lowest terms.

Worked example: Rational r3 = r1 + r2;
  1. Start from the math. a/b + c/d = (a·d + b·c) / (b·d). Reason: code is just the formula written in C++. If you can't state the math, you can't write the operator.
  2. Decide member or non-member. We'll use a member function, so r1 becomes *this and r2 is the one parameter. Reason: a binary member operator always has exactly one parameter, the right operand.
  3. Choose the parameter type: const Rational&. Reason: the reference avoids copying the object; const promises we won't change r2 and lets us pass temporaries like Rational(1, 3).
  4. Choose the return type: Rational by value. Reason: + produces a brand-new value. Returning a reference would point at a local object that dies when the function ends.
  5. Mark the function const. Reason: r1 + r2 must not modify r1. Without const, you couldn't add a const Rational on the left side.
  6. Write the body from the formula.
Rational Rational::operator+(const Rational& secondRational) const
{
  long n = numerator * secondRational.denominator
         + denominator * secondRational.numerator;   // a·d + b·c
  long d = denominator * secondRational.denominator; // b·d
  return Rational(n, d);                          // constructor reduces it
}
Trace it with Rational(1, 2) + Rational(1, 3):
n = 1·3 + 2·1 = 5  |  d = 2·3 = 6  |  result = 5/6 ✓

Notice that secondRational.denominator is legal even though it's private: member functions can access private data of any object of the same class.

Your turn: write operator*

Use the same six steps. The math is a/b · c/d = (a·c) / (b·d). Write the full definition as it would appear in Rational.cpp.

    Rational Rational::operator*(const Rational& secondRational) const
{
  long n = numerator * secondRational.numerator;     // a·c
  long d = denominator * secondRational.denominator; // b·d
  return Rational(n, d);
}
    Trace: Rational(2, 3) * Rational(3, 4) → n = 6, d = 12 → constructor reduces to 1/2.

    Self-check 2

    3. Special operators

    UnderstandApplyAnalyze

    Subscript [ ]: accessor and mutator

    Overloading [] lets you write r[0] for the numerator and r[1] for the denominator. To use it on the left side of an assignment (r[0] = 5;), it must return a reference to the data field.

    long& Rational::operator[](int index)      // & belongs to the return type
{
  if (index == 0) return numerator;
  else if (index == 1) return denominator;
  else throw runtime_error("subscript out of range");
}

    Common misconception: "Returning a plain int from operator[] is fine for assignment."

    If the function returns int by value, r[0] = 5; won't compile, because you'd be assigning to a temporary copy, not to the numerator.

    Correct reasoning: returning int& (or long&) gives the caller an alias to the real field, so the assignment changes the object. The & is part of the return type and is written before the class name: int& Rational::operator[](int index), not int Rational::&operator[]. Also note: once [] returns a reference, Rational objects become mutable.

    Compound assignment: +=, -=, *=, /=

    These change the calling object and return a reference to it so they can be chained (r2 = r1 += x;).

    Rational& Rational::operator+=(const Rational& secondRational)
{
  *this = *this + secondRational;   // reuse operator+
  return *this;
}

    Unary operators and ++ / --

    A unary member operator works on the calling object only, so it has no parameters. To tell the compiler which ++ you mean, postfix takes a dummy int parameter that is never used.

    Rational Rational::operator-() const        // unary minus: -r1
{ return Rational(-numerator, denominator); }

Rational& Rational::operator++()            // prefix: ++r1
{
  numerator += denominator;                 // adds 1 (b/b)
  return *this;                             // the NEW value
}

Rational Rational::operator++(int dummy)     // postfix: r1++
{
  Rational temp(numerator, denominator);    // save the OLD value
  numerator += denominator;
  return temp;                              // by value: temp is local
}

    Common misconception: "Prefix and postfix ++ return the same thing."

    Both add 1 to the object, but prefix evaluates to the new value and postfix evaluates to the old value. If r1 is 1/2, then r3 = r1++; sets r3 to 1/2 (and r1 to 3/2), while r3 = ++r1; sets both to 3/2.

    Correct reasoning: postfix has to copy the old state before changing it, which is why it returns a local temp by value. Prefix can return *this by reference because the object itself already holds the answer.

    Friends and the stream operators << >>

    In cout << r1, the left operand is an ostream, not a Rational. So operator<< can't be a Rational member. It's written as a non-member, and declared a friend inside the class so it can read the private fields.

    // In Rational.h, inside the class:
friend ostream& operator<<(ostream& out, const Rational& rational);
friend istream& operator>>(istream& in, Rational& rational);

// In Rational.cpp (no Rational:: prefix, no friend keyword):
ostream& operator<<(ostream& out, const Rational& rational)
{
  out << rational.numerator << "/" << rational.denominator;
  return out;   // returning the stream enables chaining
}

    Returning the stream is what makes cout << r1 << " and " << r2; work: it is evaluated as ((cout << r1) << " and ") << r2.

    Real-world application: the campus bookstore register

    The bookstore's point-of-sale program stores prices in a Money class that keeps whole cents in a long to avoid floating-point rounding errors. Overloaded operators make the checkout code read like a receipt:

    Money total;                       // $0.00
total += textbook * 1;             // Money * int  -> operator*
total += scantron * 3;
if (total > Money(100, 0))        // operator>
  total -= total * 10 / 100;       // 10% discount
cout << "Amount due: " << total;   // friend operator<< prints $123.45

    Without overloading, the same logic becomes total.addTo(textbook.times(1)), which is harder to read and easier to get wrong. The same idea powers std::string, std::chrono durations, matrix libraries, and 2D vector math in game engines.

    Self-check 3

    4. Conversions and the Big Three

    UnderstandAnalyzeEvaluate

    Object to number: a conversion operator

    To let a Rational act like a double, define operator double(). It has no return type written because the name already says what it returns.

    Rational::operator double() const
{ return doubleValue(); }

Rational r1(1, 4);
double d = r1 + 5.1;    // r1 converts to 0.25, d is 5.35

    Number to object: a conversion constructor

    A constructor with one parameter, such as Rational(int numerator), lets C++ convert an int into a Rational automatically. With it, Rational(2, 3) + 4 yields 14/3.

    But here's the puzzle: r1 + 4 works, yet 4 + r1 fails when operator+ is a member. A member operator is called on its left operand, 4.operator+(r1), and an int has no member functions. The fix is to make operator+ a non-member function taking two const Rational& parameters; then C++ can convert either side.

    Rational operator+(const Rational& r1, const Rational& r2)
{ return r1.add(r2); }      // now 4 + r1 and r1 + 4 both work

    Watch out: pick one direction

    If a class defines both operator double() and a Rational(int) conversion constructor, r1 + 4 becomes ambiguous: should C++ turn r1 into a double, or 4 into a Rational? The compiler reports an error. Define one conversion direction, not both.

    Overloading = for a deep copy

    By default, = performs a memberwise (shallow) copy. That's fine for Rational, whose fields are plain numbers. It's a bug for a class like Course that holds a pointer to a dynamic array of student names: after course1 = course2; both objects point to the same array, and the second destructor deletes memory that's already gone.

    const Course& Course::operator=(const Course& course)
{
  if (this != &course)                // 1. guard against c1 = c1
  {
    courseName = course.courseName;
    numberOfStudents = course.numberOfStudents;
    capacity = course.capacity;
    delete [] students;                 // 2. free the old array
    students = new string[capacity];     // 3. allocate our own
    for (int i = 0; i < numberOfStudents; i++)
      students[i] = course.students[i]; // 4. copy the contents
  }
  return *this;                        // 5. enables c1 = c2 = c3
}

    Common misconception: "operator= can return void since assignment doesn't produce a value."

    In C++, assignment is an expression with a value. course1 = course2 = course3; runs right to left: course3 is copied into course2, and the result (course2) is then copied into course1.

    Correct reasoning: a void return breaks chaining. Return a reference to *this instead.

    The Rule of Three

    The copy constructor, the assignment operator, and the destructor are the Big Three. The compiler generates all three for you. If your class owns a pointer to dynamic memory, you almost certainly need to write all three; if you customize one, customize the other two.
