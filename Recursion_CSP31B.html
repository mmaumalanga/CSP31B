1. What is recursion?

RememberUnderstand

A recursive function is a function that calls itself. Recursion is another form of program control: it is repetition without a loop. Instead of repeating steps, the function solves a smaller copy of the same problem.

Base case

One or more simplest cases that the function answers directly, without calling itself. The base case is what stops the recursion.

Recursive case

Every recursive call works on a smaller version of the problem, moving closer to a base case until it becomes that case.

To solve a problem recursively, break it into subproblems. If a subproblem looks like the original problem with a smaller size, apply the same function to it.

Real worldFinding files in nested folders

Your Downloads folder holds files and other folders, and those folders hold more folders. How many levels deep does it go? You don't know, and you don't need to. The structure is inherently recursive: a folder is files plus smaller folders. Search tools, backup software and your IDE's "Find in Files" all walk folder trees this way.

#include <filesystem>
namespace fs = std::filesystem;

// Count every file inside dir, at any depth (C++17)
int countFiles(const fs::path& dir) {
    int count = 0;
    for (const auto& entry : fs::directory_iterator(dir)) {
        if (entry.is_directory())
            count += countFiles(entry.path()); // recursive case: a smaller folder
        else
            count++;                           // simplest case: a plain file
    }
    return count;  // a folder with no sub-folders makes no recursive calls
}

2. Worked example: factorial

UnderstandApply Follow the reasoning step by step. You'll do one on your own right after.

Step 1: What is the simplest input?

factorial(0) is 1. No more work is needed, so this is the base case.

Step 2: Relate a hard case to a simpler one

If I already knew factorial(3) = 6, could I get factorial(4)? Yes: 4 * factorial(3) = 24.

Step 3: Generalize the pattern

factorial(n) = n * factorial(n - 1). Each call shrinks n by 1, so it always reaches 0 for any n ≥ 0.

Step 4: Write the code (combine steps 1 and 3)

long long factorial(int n) {
    if (n == 0)                    // base case (step 1)
        return 1;
    return n * factorial(n - 1);   // recursive case (step 3)
}

Step 5: Expand it by hand

factorial(4) = 4 * factorial(3)
             = 4 * (3 * factorial(2))
             = 4 * (3 * (2 * factorial(1)))
             = 4 * (3 * (2 * (1 * factorial(0))))
             = 4 * (3 * (2 * (1 * 1)))      <- base case reached, now unwind
             = 4 * (3 * (2 * 1))
             = 4 * (3 * 2)
             = 4 * 6
             = 24

Watch the call stack

Each call gets its own stack frame holding its own copy of n. Frames pile up on the way down and are removed as each call returns.

4. Common misconceptions

Misconception 1

"Recursion is faster or more efficient than a loop."

Why it's wrong: Every call has to allocate a stack frame for its parameters and local variables, then clean it up. That costs both memory and time. A loop that does the same job uses one frame. Recursion's advantage is clarity for inherently recursive problems (trees, folders, Tower of Hanoi), not speed. Naive recursive Fibonacci can be far slower, because it recomputes the same values again and again (see the Patterns tab).

Misconception 2

"As long as I write a base case, the recursion will stop."

Why it's wrong: The base case also has to be reachable. Call factorial(-1) with the code above: n goes −2, −3, −4… and never equals 0. Calls keep piling up until the program runs out of stack memory and crashes with a stack overflow. Every recursive call must move closer to a base case, and you should guard against bad input, for example with if (n <= 0) return 1;.

Misconception 3

"All the recursive calls share the same variable n."

Why it's wrong: Each call has its own frame with its own copy of every parameter and local variable. When factorial(1) runs, the n = 4 in the first frame is still waiting there, untouched. That is why each frame can finish its own multiplication when control comes back to it.

5. Recursion vs. iteration

How it repeatsThe function calls itselffor / while loop
How it stopsReaches a base caseLoop condition becomes false
MemoryOne stack frame per active callA single frame
Failure modeStack overflowInfinite loop
Best forInherently recursive problems: trees, nested folders, Tower of Hanoi, divide and conquerSimple counting or linear repetition

Any recursive function can be rewritten with a loop, sometimes with your own explicit stack. Pick whichever one makes the solution clearer, unless performance or stack depth is a real concern.

1. Helper functions: a recursive palindrome

UnderstandAnalyze

A string is a palindrome if its first and last characters match and the inside is also a palindrome. That's a smaller copy of the same problem.

// Version A: simple, but it builds a NEW string on every call
bool isPalindrome(const string& s) {
    if (s.size() <= 1) return true;                  // base case
    if (s[0] != s[s.size() - 1]) return false;       // base case
    return isPalindrome(s.substr(1, s.size() - 2));  // copies the string
}

// Version B: an overloaded HELPER function tracks low/high indexes instead
bool isPalindrome(const string& s, int low, int high) {
    if (high <= low) return true;
    if (s[low] != s[high]) return false;
    return isPalindrome(s, low + 1, high - 1);       // no copying
}
bool isPalindrome(const string& s) {                 // what callers use
    return isPalindrome(s, 0, s.size() - 1);
}

Why use a helper? Version A calls substr every time, which copies about n characters on each of about n/2 calls. Version B passes the same string by reference and only moves two indexes. The short public version keeps the interface simple for callers. Recursive problems often need extra parameters like these, so this pattern comes up a lot.

2. Recursive binary search

Apply Each call throws away half of the array, so the search takes about log2(n) calls.

int binarySearch(const int list[], int key, int low, int high) {
    if (low > high) return -low - 1;          // base case: not found
    int mid = (low + high) / 2;
    if (key < list[mid])  return binarySearch(list, key, low, mid - 1);  // case 1
    if (key == list[mid]) return mid;                                    // case 2 (base)
    return binarySearch(list, key, mid + 1, high);                       // case 3
}

3. Recursive selection sort

Understand

Find the largest number in the list and swap it with the last number. Then ignore the last number and recursively sort the smaller list that's left.

void sort(int list[], int high) {              // sorts list[0..high]
    if (high <= 0) return;                     // base case: 0 or 1 element
    int indexOfMax = 0;
    for (int i = 1; i <= high; i++)
        if (list[i] > list[indexOfMax]) indexOfMax = i;
    swap(list[indexOfMax], list[high]);       // largest goes to the end
    sort(list, high - 1);                      // sort the rest
}
void sort(int list[], int size) { sort(list, size - 1); }   // helper wrapper

4. Tower of Hanoi

UnderstandAnalyze Move all n disks from tower A to tower B. Move one disk at a time, and never put a larger disk on a smaller one.

The recursive idea: three subproblems
  1. Move the top n − 1 disks from A to C, using B as the helper.
  2. Move disk n from A to B.
  3. Move the n − 1 disks from C to B, using A as the helper.
void moveDisks(int n, char from, char to, char aux) {
    if (n == 1) {                                         // base case
        cout << "Move disk 1 from " << from << " to " << to << endl;
        return;
    }
    moveDisks(n - 1, from, aux, to);                       // step 1
    cout << "Move disk " << n << " from " << from << " to " << to << endl; // step 2
    moveDisks(n - 1, aux, to, from);                       // step 3
}
// call: moveDisks(n, 'A', 'B', 'C');

Counting moves: moves(n) = 2·moves(n − 1) + 1, with moves(1) = 1. That gives 1, 3, 7, 15, 31… = 2n − 1. For 3 disks that's 3 + 1 + 3 = 7 moves, and for 4 disks it's 7 + 1 + 7 = 15.

5. Fibonacci and the cost of repeated work Beyond the slides

AnalyzeEvaluate

// fib(0) = 0, fib(1) = 1, fib(n) = fib(n-1) + fib(n-2)
long long fib(int n) {
    if (n == 0) return 0;          // base case
    if (n == 1) return 1;          // base case
    return fib(n - 1) + fib(n - 2); // TWO recursive calls
}

Each call makes two more calls, so the number of calls grows exponentially. fib(3) is computed again inside fib(5), again inside fib(4), and so on. Try it:

The fix: memoization. Save each answer the first time you compute it, and look it up after that:

long long fibMemo(int n, vector<long long>& memo) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];               // already computed
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}
