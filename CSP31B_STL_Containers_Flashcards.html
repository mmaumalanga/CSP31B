1 STL basics: containers, iterators and algorithms

Linked lists, queues, priority queues and search trees are used everywhere in real programs. Instead of writing them yourself, C++ gives you the Standard Template Library (STL), developed by Alexander Stepanov and Meng Lee at Hewlett-Packard. Its classes and functions are templates, so they work with any element type: vector<int>, vector<string>, and so on.

The STL has three components that work together:

  • Containers store a collection of elements (for example, a vector).
  • Iterators are pointer-like objects for moving through a container’s elements.
  • Algorithms (about 80 of them, such as sort and find) manipulate data, and most reach the elements through iterators.

The containers fall into three categories:

Sequence (linear)vector · deque · list
Elements kept in the order you put them.
Associative (non-linear)set · multiset · map · multimap
Sorted by key for fast lookup.
Container adaptersstack · queue · priority_queue
Restricted versions of sequence containers.

Sequence and associative containers are called first-class containers. All containers share functions such as empty(), size(), operator= and the relational operators; first-class containers also have begin(), end(), rbegin(), rend(), clear(), erase(), swap() and max_size().

ContainerHeaderBest for
vector<vector>Direct access to any element; quick insert/delete at the end
deque<deque>Direct access; quick insert/delete at the front and the end
list<list>Rapid insert/delete anywhere
set / multiset<set>Direct lookup; set has no duplicates, multiset allows them
map / multimap<map>Key/value pairs; map has unique keys, multimap allows duplicate keys
stack<stack>Last-in, first-out (LIFO)
queue / priority_queue<queue>First-in, first-out (FIFO) / highest priority removed first
Misconception: “All STL containers inherit from one base class, like Container.” Wrong. C++ does not define a base class for containers. They share common functions by convention: each class was designed with the same function names (size(), empty(), begin()…). That’s why algorithms are written to work with iterators instead of a common base type.

2 Iterators: moving through a container

c.begin() returns an iterator to the first element. c.end() returns an iterator to the position one past the last element; it is a stop marker, not an element. The standard loop:

vector<int> v = {10, 20, 30};
for (vector<int>::iterator p = v.begin(); p != v.end(); p++)
    cout << *p << " ";            // 10 20 30

for (auto p = v.rbegin(); p != v.rend(); p++)   // C++11 auto, reverse order
    cout << *p << " ";            // 30 20 10

Five iterator categories

CategoryCan doExtra operators
InputRead elements, move forward one at a time*p (read), ==, !=, ++
OutputWrite elements, move forward one at a time*p (write), ++
ForwardRead and write, move forwardinput + output
BidirectionalForward, plus move backward--p, p--
Random-accessBidirectional, plus jump any number of elementsp += i, p + i, p[i], <, >

Which containers support which? vector and deque: random-access. list, set, multiset, map, multimap: bidirectional. stack, queue, priority_queue: no iterators.

Related tools: a const_iterator can read but not change elements; a reverse_iterator (rbegin()/rend()) walks backward; typedef creates type synonyms (typedef int integer;), and C++11 auto lets the compiler infer long iterator types. ostream_iterator<int> out(cout, " "); with copy(v.begin(), v.end(), out); prints a container, and istream_iterator reads input.

Worked example: tracing a random-access iterator Apply 
vector<int> v = {10, 20, 30, 40, 50};
auto p = v.begin();
p += 2;
cout << *p << " " << p[1] << " ";
--p;
cout << *(p + 3) << " " << (v.end() - v.begin());
  1. p = v.begin(): p is at index 0 (value 10).
  2. p += 2: jump two places to index 2. *p is 30.
  3. p[1] means “one past p” without moving p: index 3, 40.
  4. --p: back one to index 1 (value 20). *(p + 3) is index 4, 50.
  5. v.end() - v.begin(): the distance from the first element to one-past-the-last is the size, 5.
1020 ←p304050end()
Output: 30 40 50 5. Reasoning rule: +=, -- and ++ move p; p + i and p[i] only look.

Your turn Apply: vector<int> v = {5, 15, 25, 35}; auto p = v.end(); p -= 3; cout << *p; p++; cout << p[1];

Misconception: “end() points to the last element, so *v.end() gives the last value.” Wrong. end() refers to the position after the last element. Dereferencing it is undefined behavior: it may print garbage or crash. Use v.back(), *(v.end() - 1) or *v.rbegin() for the last element. That’s also why loops test p != v.end().

3 Sequence containers: vector, deque and list

vector and deque are implemented with arrays; list is a (doubly) linked list. All three share push_back, pop_back, front(), back(), insert(position, elem), assign(n, elem) and assign(beg, end).

deque<int> d;
d.push_back(4);
d.push_front(2);
d.push_back(6);
d.push_front(0);
d.pop_back();
d.insert(d.begin() + 1, 9);

Your turn Apply: list<int> lst = {7, 3}; lst.push_front(1); lst.push_back(9); lst.sort(); lst.pop_front();

Misconception: “Every container works with sort(c.begin(), c.end()).” Wrong. The sort algorithm needs random-access iterators so it can jump around. A list only has bidirectional iterators, so sort(lst.begin(), lst.end()) does not compile. Use the member function lst.sort() instead. The iterator category decides which algorithms a container can use.

4 Associative containers: set, multiset, map and multimap

Associative containers store elements sorted by key (using < by default) for fast storage and lookup. Common functions:

  • find(key): iterator to the element with that key (or end() if none).
  • count(key): how many elements have that key.
  • lower_bound(key): iterator to the first element with that key (first element ≥ key).
  • upper_bound(key): iterator to the element just after the last one with that key.

set stores unique values; multiset allows duplicates. map stores unique keys with values (pair<key, value>, accessed by first and second); multimap allows duplicate keys.

Worked example: set vs. multiset Apply 
int values[] = {5, 3, 5, 1, 5};
set<int> s(values, values + 5);
multiset<int> ms(values, values + 5);
  1. set: each value is inserted in sorted position; the 2nd and 3rd 5 are rejected as duplicates. Contents: 1 3 5, size 3.
  2. multiset: duplicates are kept, still sorted. Contents: 1 3 5 5 5, size 5.
  3. ms.count(5) is 3; s.count(5) is 1 (a set’s count is always 0 or 1).
  4. *ms.lower_bound(4): the first element ≥ 4 is 5. ms.upper_bound(5) is end(), because nothing comes after the last 5.
Reasoning rule: associative containers ignore insertion order; they always keep elements sorted.

map and the subscript operator

map<string, int> grades;
grades["Ana"] = 90;
grades.insert(pair<string, int>("Ben", 85));
for (auto p = grades.begin(); p != grades.end(); p++)
    cout << p->first << ": " << p->second << endl;

Your turn Apply: map<string, int> grades; grades["Ana"] = 90; grades["Ben"] = 85; grades["Ana"] = 95; cout << grades["Cal"];

Misconception: “grades["Cal"] just looks up Cal, so it can’t change the map.” Wrong. If the key isn’t there, operator[] inserts it with a default value (0 for int, "" for string). To check whether a key exists without adding it, use grades.find("Cal") != grades.end() or grades.count("Cal").
Real-world application: counting words in a discussion post Canvas-style plagiarism and readability tools count how often each word appears. A map<string, int> does it in one line per word, and prints the words in alphabetical order for free: 
map<string, int> freq;
string word;
while (cin >> word)
    freq[word]++;            // a new word starts at 0, then becomes 1
for (auto p = freq.begin(); p != freq.end(); p++)
    cout << p->first << " " << p->second << endl;
Here, operator[]’s automatic insert is exactly what we want.

5 Container adapters: stack, queue and priority_queue

Adapters are built on top of a sequence container and allow access at only one end, for special cases. You can choose the underlying container, for example stack<int, vector<int>>; stack and queue use a deque by default, and priority_queue uses a vector by default (a deque also works).

AdapterRuleAddLookRemove
stackLast in, first outpush(x)top()pop()
queueFirst in, first outpush(x) (at the back)front(), back()pop() (from the front)
priority_queueLargest (highest priority) firstpush(x)top()pop()
Worked example: the same pushes, three adapters Apply

Push 3, 1, 4, 1, 5 into each, then repeatedly print the next element and pop() until empty:

while (!s.empty()) { cout << s.top() << " "; s.pop(); }
  1. stack: the last item pushed is on top, so they come out in reverse: 5 1 4 1 3.
  2. queue: the first item pushed is at the front, so they come out in the same order: 3 1 4 1 5.
  3. priority_queue: the largest value is always on top, regardless of order: 5 4 3 1 1.
Reasoning rule: ask “which element does this adapter consider next?” Newest (stack), oldest (queue) or largest (priority_queue).

Your turn Apply: push 8, 2, 6 into a stack, a queue and a priority_queue.

Misconception: “int x = s.pop(); removes the top and gives it to me.” Wrong. pop() returns void; it only removes. Read the element first with top() (or front() for a queue), then call pop(). Also check empty() first: calling top() or pop() on an empty adapter is undefined behavior.
Real-world application: the Delta IT help desk Walk-in tickets are served in arrival order (queue). Urgent issues such as “Canvas is down for a class” jump ahead (priority_queue ordered by urgency). The ticket editor’s Undo button reverses the most recent change first (stack). Each staff member is mapped to their open tickets (multimap).

Higher-order challenges

Analyze Analyze: Explain why stack, queue and priority_queue provide no iterators, while vector provides random-access iterators. Connect your answer to each container’s purpose.

Model answer: An adapter’s whole purpose is to restrict access to one element: the top of a stack, the front of a queue, the highest priority item. Iterators would let code walk through and change any element, which would break the LIFO, FIFO or priority rule the adapter guarantees. A vector is meant for general storage with direct access to any element, and it’s stored in an array, so jumping to any position is cheap; random-access iterators expose exactly that ability.

Check your answer:

  • Did you say adapters deliberately limit access?
  • Did you explain that iterators would break the adapter’s rule?
  • Did you connect vector’s array storage to random access?

Evaluate Evaluate: Choose the best container for each task and justify each choice: (a) a browser’s Back button, (b) a phone contact list looked up by name, (c) print jobs served in order, (d) the list of unique students who attended office hours this week.

  • (a) stack: the most recently visited page is the first one you go back to (LIFO).
  • (b) map<string, string>: fast lookup by a unique key (name), kept in alphabetical order. A multimap is also defensible if two contacts can share a name.
  • (c) queue: first job sent is first printed (FIFO). A priority_queue fits if some jobs are urgent.
  • (d) set<string>: duplicates are dropped automatically, and names print sorted.

Check your answer: each choice names a specific container · the justification uses its rule (LIFO, FIFO, unique, sorted, key lookup) · you considered at least one alternative.

Create Create: Write a C++ program that reads exam scores until the user enters -1, then prints (1) the scores in descending order, (2) how many times the most common score appears and (3) the top three scores. Use at least two different STL containers and explain why you chose each.

#include <iostream>
#include <set>
#include <queue>
using namespace std;

int main() {
    multiset<int> scores;          // sorted, keeps duplicate scores
    priority_queue<int> top;       // largest score always on top
    int s;
    while (cin >> s && s != -1) {
        scores.insert(s);
        top.push(s);
    }

    cout << "Descending: ";
    for (auto p = scores.rbegin(); p != scores.rend(); p++)
        cout << *p << " ";

    int best = 0;
    for (auto p = scores.begin(); p != scores.end(); p = scores.upper_bound(*p))
        if ((int)scores.count(*p) > best) best = scores.count(*p);
    cout << "\nMost common score appears " << best << " time(s)\n";

    cout << "Top three: ";
    for (int i = 0; i < 3 && !top.empty(); i++) {
        cout << top.top() << " ";  // read first...
        top.pop();                  // ...then remove
    }
    cout << endl;
    return 0;
}

Why these containers: a multiset sorts automatically and keeps duplicates, so a reverse iterator prints descending order and count() finds repeats; upper_bound(*p) skips to the next distinct score. A priority_queue hands back the largest score each time. (A map<int, int> of score → count is another good design.)

Check your answer: stops at -1 · correct descending output · duplicates counted · reads with top() before pop() and checks empty() · container choices justified.
